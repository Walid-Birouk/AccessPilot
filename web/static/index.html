AccessPilot tests a shop's key pages in a real browser, merges the defects the way a theme is actually fixed, and puts the checkout first. You get a prioritised fix plan, a draft accessibility statement and proof of progress over time.

Live scans test up to 8 pages in about a minute, honour robots.txt, and never click, type or buy anything.

    How it works

    From an address to a plan a developer can act on

    1. 1

      Crawl by template

      Classifies pages as home, category, product, cart, checkout… and samples a few of each, so twenty pages cover the whole theme. Read-only: GET requests only, robots.txt honoured, rate-limited, with a circuit breaker.

    2. 2

      Test in a real browser

      Runs axe-core against WCAG 2.1 AA in headless Chromium after client-side rendering settles, even on sites with a strict Content-Security-Policy. Pages that fail to load are reported as untested, never as clean.

    3. 3

      Merge into fixes

      Findings of the same rule on the same template become one fix. Elements shared by every page, like the header or menu, become one layout fix. The list is ordered by impact, then by place in the purchase path.

    4. 4

      Prove progress

      Each scan is compared with the previous one (fixed, new, still present) and recorded in a hash-chained log with the SHA-256 of the scan file, so the work can be shown to a regulator or a client.

    What you get

    Four outputs from one command

    A prioritised fix plan

    In French, for the French market, with the RGAA criterion, the WCAG reference, the failing HTML and concrete instructions for each fix.

    A draft accessibility statement

    The déclaration d'accessibilité in the RGAA model format, declared “non conforme” until a human audit says otherwise.

    A diff and a CI gate

    --fail-on serious or --fail-on-new makes a theme deploy fail when it adds accessibility regressions.

    A tamper-evident history

    An append-only, hash-chained evidence log. accesspilot verify checks the chain and every scan file it references.

    What it is not

    Honest by design

    Automated testing finds only part of accessibility defects. AccessPilot never says a site is compliant: every report says so on its first line and lists what automation cannot test, and the statement stays “non conforme” until an auditor says otherwise. An optional LLM can rewrite fix instructions, but its output must pass the same claim guard and may only cite that fix's own evidence.

    Engineering

    Built to be trusted

    • Python 3.11+, Playwright, axe-core vendored with French messages, no CDN at scan time
    • Deterministic: every report, plan and statement is derived from one immutable scan.json
    • Tests against a local fixture shop with a strict CSP, broken pages and links it must never follow
    • This demo: a standard-library server with per-visitor quotas, a scan queue and SSRF protection on every browser request
    • The page you are reading is itself checked with axe-core in the test suite
